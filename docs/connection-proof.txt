What this proves
----------------
On startup, the backend establishes a LIVE JDBC connection to the
Supabase PostgreSQL database (not a mock/in-memory DB). The log below is
produced by HikariCP (the connection pool) and Hibernate reporting the
real database it connected to — the JDBC URL, driver, dialect, and the
server's reported version (17.6) can only be obtained from an actual
live connection.

Where the connection is configured in the project
--------------------------------------------------
Database (backend -> Supabase):
    backend/src/main/resources/application-local.properties      (real URL + credentials; gitignored)
    backend/src/main/resources/application-local.properties.example  (committed template)
    backend/pom.xml                                              (org.postgresql:postgresql JDBC driver)
    backend/src/main/java/edu/cit/erag/souvenirpos/repository/   (Spring Data JPA repositories use the DataSource)

API (clients -> backend):
    web/src/api/client.js                                        (axios baseURL '/api')
    web/vite.config.js                                           (dev proxy -> http://localhost:8080)
    mobile/.../data/network/ApiService.kt                        (Retrofit endpoints)
    mobile/app/build.gradle.kts                                  (API_BASE_URL = http://10.0.2.2:8080/api/)

Note
----
A later "HikariPool-1 - Failed to validate connection ... This connection
has been closed" WARN line (if present in the full log) is NOT an error:
it is the Supabase pooler dropping an idle connection, which HikariCP
detects and replaces automatically.
